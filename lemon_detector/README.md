# Lemon detector — YOLOv11 ที่จับเฉพาะหน้าเรา

โมเดล object detection คลาสเดียว ป้ายกำกับ `Lemon(me):3`
เขียนด้วย Python ล้วน ต่อยอดจาก `yolo11n.pt` ที่มีอยู่แล้วในโปรเจกต์

ปลายทางคือ export เป็น `.onnx` ไปแทนโมเดล COCO บนปุ่มรูปโปรไฟล์ในหน้าเว็บ
จากเดิมที่กดแล้วขึ้น `person 0.92` (โมเดลสำเร็จรูปของคนอื่น)
กลายเป็น `Lemon(me):3 0.9x` — **โมเดลที่เราเทรนเอง**

---

## ⚠️ อ่านก่อนเริ่ม 3 ข้อ

### 1. ผมโหลดรูปจากลิงก์ Google Photos ให้ไม่ได้

ลิงก์ที่ส่งมาสองอันเป็นหน้าเว็บที่เรนเดอร์ด้วย JavaScript และตัวไฟล์รูปจริง
อยู่หลัง URL ชั่วคราวของ `lh3.googleusercontent.com` — ดึงแบบอัตโนมัติไม่ได้
และผมก็ไม่ควรไปดูดรูปส่วนตัวมาเก็บไว้เองอยู่ดี

**สิ่งที่ต้องทำเอง:** เปิดอัลบั้ม → กดโหลดทั้งอัลบั้ม → แตกไฟล์ → วางรูปไว้ที่

```
lemon_detector/raw/me/
```

### 2. ต้องมีรูป "หน้าคนอื่น" ด้วย ไม่งั้นโจทย์ไม่สำเร็จ

โจทย์คือ *"ตรวจจับเฉพาะหน้าผมเท่านั้น"* ซึ่ง detection คลาสเดียวทำเองไม่ได้

ถ้าเทรนด้วยรูปหน้าเราอย่างเดียว โมเดลจะสรุปว่า **"หน้าคน = คลาส 0"**
แล้วเวลาเจอหน้าคนอื่นมันก็จะตีกรอบให้เหมือนกัน เพราะไม่เคยเห็นตัวอย่างไหน
ที่บอกว่า *"นี่คือหน้า แต่ไม่ใช่คลาส 0"* เลยสักใบ

วิธีแก้คือใส่ **hard negative** — รูปหน้าคนอื่นที่ label เป็นไฟล์เปล่า
YOLO จะนับเป็นพื้นหลัง แล้วโดนลงโทษทุกครั้งที่ตีกรอบลงไป
โมเดลเลยถูกบังคับให้หาความต่างระหว่างหน้าเรากับหน้าคนอื่นให้เจอ

```
lemon_detector/raw/not_me/     ← หน้าคนอื่น ยิ่งหลากหลายยิ่งดี
```

จำนวนที่แนะนำ:

| โฟลเดอร์ | จำนวนขั้นต่ำ | ที่อยากได้ |
|---|---|---|
| `raw/me` | 80 รูป | 200–400 รูป (หลายมุม หลายแสง หลายทรงผม มี/ไม่มีแว่น) |
| `raw/not_me` | เท่ากับ `raw/me` | 2–3 เท่าของ `raw/me` |

หา `not_me` จากรูปกลุ่มเพื่อน รูปในเน็ต หรือ dataset ใบหน้าสาธารณะก็ได้
ยิ่งมีคนที่หน้าตา/เพศ/อายุใกล้เคียงเรา ยิ่งบังคับให้โมเดลเรียนละเอียดขึ้น

### 3. auto-label ใช้ Haar cascade — ต้องเปิดตรวจด้วยตา

`prepare_dataset.py` หาใบหน้าให้อัตโนมัติ จะได้ไม่ต้องลากกรอบเองหลายร้อยใบ
แต่ Haar เก่งเฉพาะ **หน้าตรง** ถ้าเอียงมากหรือหันข้างจะหาไม่เจอ
สคริปต์เลยเซฟรูปที่วาดกล่องแล้วไว้ที่ `review/` ให้เปิดดูก่อนเทรนทุกครั้ง

> **label ผิดหนึ่งใบ เสียหายมากกว่ามีรูปน้อยลงหนึ่งใบ** — เจอกล่องเพี้ยนให้ลบรูปต้นทางทิ้ง

## ใช้งาน 4 ขั้น

### 1. เตรียมชุดข้อมูล

```bash
python prepare_dataset.py
```

อ่าน `raw/me` + `raw/not_me` → หาใบหน้า → เขียน label → แบ่ง train/val/test
→ สร้าง `dataset/` กับ `data.yaml` → เซฟรูปตรวจทานไว้ที่ `review/`

**เปิด `review/ok/` ดูก่อนไปขั้นถัดไป** ถ้ากล่องวางผิด ลบรูปต้นทางแล้วรันใหม่

รูปหมู่ที่เจอหลายหน้าจะถูก**ข้าม**โดยอัตโนมัติ (เพราะเดาไม่ได้ว่าหน้าไหนคือเรา)
ไปกองไว้ที่ `review/no_face_or_ambiguous/` — ถ้าอยากให้เดาว่าหน้าใหญ่สุดคือเรา:

```bash
python prepare_dataset.py --multi largest
```

### 2. เทรน

```bash
python train.py
```

เริ่มจาก `yolo11n.pt` (transfer learning — ชุดข้อมูลหลักร้อยรูปเทรนจากศูนย์ไม่มีทางลู่เข้า)
จบแล้วจะวัดผลบนชุด test ให้ พร้อมบอก mAP / precision / recall

ปรับได้: `--epochs 200` · `--batch 8` (ถ้า VRAM ไม่พอ) · `--device cpu`

ผลอยู่ที่ `runs/lemon/` — น้ำหนักที่ดีที่สุดคือ `runs/lemon/weights/best.pt`

### 3. ลองใช้

```bash
python predict.py --source ../public/me.jpg    # รูปเดียว
python predict.py --source raw/not_me          # ← เทสต์ที่สำคัญที่สุด
python predict.py --source 0                   # เว็บแคมสด กด q ออก
```

> **เทสต์ที่ต้องผ่านจริง ๆ คือ `--source raw/not_me`**
> ถ้ารันแล้วขึ้นกล่องบนหน้าคนอื่น = ยังแยกตัวบุคคลไม่ได้
> แก้ด้วยการเพิ่มรูปใน `raw/not_me` แล้วเทรนใหม่

### 4. export ไปใช้บนเว็บ

```bash
python export_onnx.py
```

- export เป็น `.onnx` (opset 12 — เวอร์ชันที่ `onnxruntime-web` บน CDN รองรับแน่นอน)
- ก๊อปไปวางที่ `../public/models/lemon.onnx`
- รันบน `../public/me.jpg` แล้ว**พิมพ์บล็อกโค้ดให้ก๊อปไปวางใน `lib/content.ts`**

ในบล็อกนั้นมี 4 ค่าที่ต้องเอาไปแก้ใน `DETECTOR`:

| ค่า | ความหมาย |
|---|---|
| `modelUrl` | ชี้ไปที่ `/models/lemon.onnx` แทนของเดิม |
| `classNames` | `["Lemon(me):3"]` — ไม่ใส่ เว็บจะไปอ่านชื่อจาก COCO แล้วขึ้นว่า `person` |
| `photoW` / `photoH` | ขนาดจริงของรูปโปรไฟล์ |
| `fallback` | ผลที่รันไว้ล่วงหน้า ใช้ตอนโหลดโมเดลไม่สำเร็จ |

ฝั่ง `PhotoDetect.tsx` ไม่ต้องแก้อะไรแล้ว — ตัว `decode()` อ่านจำนวนคลาสจาก
`dims[1]` อยู่แล้ว โมเดล 1 คลาสจะได้ tensor `[1, 5, 8400]` แทน `[1, 84, 8400]`
และมันวนลูปตามขนาดจริง ไม่ได้ฮาร์ดโค้ดเลข 84 ไว้

## โครงไฟล์

```
lemon_detector/
├── config.py             ← ค่าคงที่ทั้งหมด แก้ที่นี่ที่เดียว
├── prepare_dataset.py    ← ขั้น 1 auto-label + แบ่งชุด
├── train.py              ← ขั้น 2 เทรน
├── predict.py            ← ขั้น 3 ลองใช้
├── export_onnx.py        ← ขั้น 4 export + พิมพ์โค้ดให้ก๊อป
├── raw/me/               ← รูปเรา (ใส่เอง)
├── raw/not_me/           ← รูปคนอื่น (ใส่เอง)
├── dataset/              ← สร้างอัตโนมัติ
├── review/               ← สร้างอัตโนมัติ ต้องเปิดดู
├── runs/                 ← ผลการเทรน
└── out/                  ← ผลจาก predict.py
```

`dataset/`, `review/`, `runs/`, `out/`, `raw/` และ `data.yaml` เป็นของที่สร้างใหม่ได้เสมอ
ไม่ต้องเอาขึ้น git — ดูใน `.gitignore`

## ข้อจำกัดที่ต้องรู้ (และควรเขียนตรง ๆ ถ้าเอาลง portfolio)

1. **นี่ไม่ใช่ face recognition** เป็น detection คลาสเดียวที่ถูกกดด้วย hard negative
   ให้ยิงเฉพาะหน้าเรา วิธีที่ถูกต้องกว่าสำหรับงานจริงคือ detect หน้าก่อน
   แล้วค่อยเทียบ embedding — แม่นกว่ามากและเพิ่มคนใหม่ได้โดยไม่ต้องเทรนใหม่
   แต่แลกมาด้วยสองโมเดลต่อกัน ซึ่งเกินความจำเป็นของ gimmick บนหน้าเว็บ
2. **ยังไม่รู้ว่าแยกได้ดีแค่ไหนจนกว่าจะเทสต์กับหน้าที่ไม่เคยเห็น**
   mAP ที่ `train.py` พิมพ์ออกมาวัดจากชุด test ของเรา ซึ่งเป็นรูปคนละใบแต่**คนเดิม**
   ตัวเลขนั้นบอกแค่ว่า "หาหน้าเจอ" ไม่ได้บอกว่า "ไม่หลงหน้าคนอื่น"
   ตัวเลขที่ควรเอาไปเคลมคือ **false positive rate บนชุดหน้าคนอื่นที่ไม่เคยอยู่ใน `raw/`**
3. **Haar cascade พลาดหน้าเอียง/หันข้าง** ชุดข้อมูลจึงเอียงไปทางหน้าตรง
   โมเดลก็จะเก่งเฉพาะหน้าตรงตามไปด้วย
4. **ไฟล์ `.onnx` ~10 MB** คนกดปุ่มบนเว็บต้องโหลด — เลยต้องคงดีไซน์ "กดก่อนถึงโหลด" ไว้
